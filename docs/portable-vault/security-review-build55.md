| Issue | Remediation / remaining acceptance |
| --- | --- |
| [D2S-165](https://linear.app/d2sci/issue/D2S-165) | Secondary password changes no longer read or compare the primary credential. If a password is deliberately changed to match the primary password, normal login selects the secondary vault. It cannot expose the primary vault or identify the collision through rejection. Changing the secondary password away restores ordinary primary-password routing; neither library data secret changes. Use distinct passwords in normal operation. |
| [D2S-166](https://linear.app/d2sci/issue/D2S-166) | Password budgets retain their device-only Keychain account and reservation IDs, but version2 stores remaining delay and a process-epoch monotonic checkpoint. Date is display-only. Same-process elapsed time earns credit; a new process resumes the last persisted remaining wait. Restart before another checkpoint may extend the wait, up to the configured bounded delay; leaving the app/process running lets the cooldown finish. Old version1 records resume one conservative bounded wait rather than trust an adjustable date. No destructive lockout. |
| [D2S-167](https://linear.app/d2sci/issue/D2S-167) | Keychain ownership metadata guards Face ID enrollment/removal. An unmarked legacy enabled enrollment is primary-owned. A secondary session cannot replace or disable another vault's enrollment; UI hides unavailable controls without explanation. Primary management may remove its assignment, after which the user may enable Face ID from the secondary library. Secondary-owned enrollment can be managed there; primary management remains authorized. In-flight enrollment rechecks ownership/session. |
| [D2S-168](https://linear.app/d2sci/issue/D2S-168) | Current-password verification, password changes and Face ID enrollment reserve from a persistent selected-vault settings budget before verification. Password-change UI no longer performs an extra unbudgeted precheck. Failed reservations cannot modify either credentials or biometrics. Settings budgets survive view recreation/relogin and are isolated from other vaults. |
| [D2S-169](https://linear.app/d2sci/issue/D2S-169) | A missing optional secondary credential performs the same600000-round KDF work as a modern secondary check instead of returning instantly. This reduces the gross extra-derivation difference, not a constant-time or forensic-deniability guarantee. I/O, old wrappers, biometric state and filesystem/Keychain namespaces can still differ. Runtime timing evaluation remains tracked. |
| [D2S-170](https://linear.app/d2sci/issue/D2S-170) | New installations and newly changed credentials use600000-round versioned wrappers. Older authenticated wrappers remain readable without silent conversion. For the sole pre-release test owner, explicitly change main/album passwords or create fresh disposable samples if stronger wrapping is desired; no reset or migration is performed. Authenticated atomic upgrades remain follow-up work. This is not a weaker new-install default. |
| [D2S-171](https://linear.app/d2sci/issue/D2S-171) | Unreferenced FileReencryptionService removed. Retired calculator model/view-model moved into test-only fixtures; neither is compiled in the application. Retirement/notification tests remain. Original upstream history/provenance and supported encryption readers remain available. |
| [D2S-172](https://linear.app/d2sci/issue/D2S-172) | Secondary settings have no alternative-configuration badge/row. Ineligible Face ID navigation AND security-card summary are hidden. Eligible secondary biometric consent uses ordinary library text, without assigned-vault/passcode-routing language. Direct protected screen has no unavailable controls.
