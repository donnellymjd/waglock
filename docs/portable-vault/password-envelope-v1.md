# Password-envelope v1 — pre-release hardening

D2S-157. Owner clarified on October 23 that they are the only user, current vaults are disposable, and compatibility with released users becomes mandatory after 1.0. No reset or deletion is needed for this change. Automatic review initially rejected an untested integration; an unused candidate was then tested before integration. The format below is separate from native media encryption and does not change implicit legacy parameters.

New owner credential writes (setup or explicit password change) and new/reprotected album factors use PBKDF2-HMAC-SHA256 with **600,000 rounds**, a random 16-byte salt and a 32-byte key. AES-256-GCM uses a random nonce. Existing owner records, album wrappers and media remain readable without automatic rewriting. Existing credentials are strengthened only through an explicit password/protection change. An older app cannot read the new wrapper; do not downgrade this candidate onto its predecessor.

Binary layout: ASCII `WLPE`, version byte `1`, unsigned big-endian rounds `00 09 27 c0`, 16-byte salt, then CryptoKit AES-GCM combined bytes (12-byte nonce, ciphertext, 16-byte tag). The full 25-byte header and the UTF-8 purpose string are additional authenticated data. Purposes are `owner:` plus the existing Keychain service, or `album:` plus the album UUID. The decrypted owner payload additionally checks its service/version; album material checks its UUID. Unknown versions/parameters and oversized/truncated envelopes are rejected before expensive derivation. Only the known fixed parameters are accepted; attacker-controlled unbounded work is not supported.

Legacy data without the `WLPE` prefix uses the existing authenticated reader. Invalid new headers cannot authenticate as legacy ciphertext. No successful read upgrades or rewrites the source. Explicit password changes retain the same random data secret and atomic single-record replacement; injected write failures must retain the previous usable record. This does not change native file streams, metadata envelopes, age exports or passwords in existing backups. Short PINs remain guessable offline; throttling protects online use only. Random data keys do not eliminate guessing against their password wrappers.

Tests cover wrong/exact UTF-8 passwords including punctuation and NUL; purpose substitution; header, salt and ciphertext changes; truncation; unknown rounds; and legacy readers. A public fixed fixture uses Python/OpenSSL `hashlib.pbkdf2_hmac` at 600,000 rounds, independently checking the CommonCrypto derivation. Credential/album integration tests cover retained secrets, explicit changes, stale legacy records and interrupted writes. Physical-device latency and password/album/backup acceptance remain release gates. This is not an independent cryptographic audit.
