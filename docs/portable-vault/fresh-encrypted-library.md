# Fresh encrypted release library — build 45

This implements the owner's instruction to finish a narrow first release. It creates a **new library in a separate app identity**, not an in-place conversion. `config/AppStore.xcconfig` selects `com.d2sci.waglock`, version 1.0, and `WAGLOCK_ENCRYPTED_LIBRARY=YES`; the actual Info.plist must contain `WagLockEncryptedLibrary=YES`. Default WagLock Dev (`com.d2sci.vaultito.dev`) retains its existing store and credentials. Never uninstall it or claim its data was migrated.

## Protection and writes

New owner credentials use an independently random data secret retained across login-password changes. A random library root key is authenticated and wrapped under that secret. Purpose/domain-separated AEAD protects encoded media metadata and thumbnails, albums and policies, notes and drafts in a ciphertext SQLite index. HMAC tokens and authenticated inventory bind record identity and completeness. The UI uses an autosave-disabled **memory-only** SwiftData projection. Incremental saves commit a single encrypted transaction before acknowledging the projection; uncertain outcomes revoke the mount and retain potentially committed files/keys for reconciliation. Explicit album key/password boundaries remain enforced.

The fresh descriptor repeats its version/domain inside the authenticated envelope. A create-only device Keychain anchor binds the published identity; unavailable Keychain reads are errors, not absence. A missing anchored root, substituted descriptor, corrupt index or unexpected legacy/original files fails closed. No reset, credential inference, source deletion or fallback plaintext store is performed. There is no automatic replacement-library creation after loss.

Creation stages a protected sibling directory, exclusively publishes/fsyncs its descriptor and empty index, verifies the empty inventory, then exclusively renames the directory before establishing the anchor. Known interrupted empty stages can resume; unknown content and symlinks are preserved and rejected. A published root is never treated as an empty stage. Whole authentic database rollback remains undetected; this anchor is identity binding, not a monotonic revision service.

## Recovery and exclusions

The native folder plus a login password is **not** a supported portable recovery format. Device-only Keychain material is required. Reinstallation or automatic iOS backup transfer must not be assumed to restore it. Users must keep independent originals and explicitly create an age backup. The independent open-source helper and official age CLI recover supported media, album hierarchy, notes and drafts without phone/Keychain access; separately protected domains require their own export passwords. Face ID-only copies require consent and a new export password. Device preferences and biometric registrations are excluded. This is desktop extraction, not an in-app restore wizard.

Public release hides inherited presentation-only Guest Mode and refuses guest credentials; it does not implement the requested independent alternative vault. Ordinary appearance/lock preferences remain in app preferences. No new Cryptomator dependency or native-format conversion is approved.

## Import and lifetime corrections

Photos imports preserve the encoded file representation supplied by Apple's picker; Files image imports preserve supplied bytes too. Thumbnails may be recompressed separately. This does not preserve a Photos edit history or Live Photo motion component. Keep source originals. Provider callbacks copy into strictly owned protected UUID directories before the provider URL expires; cleanup never scans unknown media.

Password changes replace the mounted projection. Gallery tasks must not fault old live models after that replacement. Missing-file cleanup previously both deleted records automatically and could crash during remount; it has been removed. Video thumbnail tasks now use immutable snapshots. Explicit nonisolated destruction on scoped import/metadata classes avoids an observed iOS 18.4 actor-backdeployment invalid free.

## Evidence and limits

279 unit/security tests pass after the final gallery remount correction; the validation ledger is in [submission preparation](../release/submission-plan.md) and [build evidence](../../BUILD_ERRORS_SUMMARY.md). Tests cover every bootstrap publication checkpoint, wrong passwords, unavailable anchors, substituted/missing roots, corruption, symlinks, revocation, draft failures and atomic batches beyond the rehearsal limit. A 1,000-record/24 KiB-thumbnail sample saved in 2.91 seconds and reopened in 1.55 seconds on simulator. This is measured evidence, not a bound on all phone libraries: decoded UI projections still consume memory, and native index/page/payload limits apply.

The checked-in [encrypted-library recovery fixture](../../tools/fixtures/encrypted-library-backup/README.md) is generated by an actual encrypted iOS-simulator mount and backup service. Official age 1.3.2 recovers seven byte-matching PNG/MOV/PDF/WAV payloads, Unicode names, notes/drafts and nested password domains. Parent-only passwords, tampering and truncation are rejected. No private media or owner vault was used.

No independent security-audit certification, secure deletion, forensic deniability, whole-copy rollback prevention, legacy metadata conversion or universal cloud-upload guarantee is claimed. Physical-device acceptance and Apple account declarations remain required before submission.
