# Code review of the redesign branch — 2026-11-10

An AI-assisted review of `claude/optimistic-babbage-ned59x` against `main` (high effort, unverified findings), run before resubmitting to the App Store. It is not an independent security review. The owner has tested the redesign builds on their iPhone; the fixes below were made after that testing and haven't been compiled or run.

## Fixed

| # | Finding | Fix |
| --- | --- | --- |
| 1 | Deleting a library didn't give its space back to the fixed-size reserve, so WagLock's iOS-visible size dropped and showed that a library was deleted. | `LibraryContentRemover` invalidates reserve usage and posts `wagLockStorageChanged` after removing the files. |
| 2 | Live Photo playback didn't recheck the session between its two decrypts or after building the Live Photo, so it could decrypt the motion or start playback after lock. | `LivePhotoPlaybackView.load` and the album preview recheck after every await and discard late copies. |
| 3 | Verifying the current passcode (Face ID setup, backup with the current passcode) ran scrypt (64 MiB) on the main thread, freezing the UI. | New `verifyPasswordForSecurityOperation` goes through `LibraryPasscodeService.verify`, which runs off the main thread and shares the lock-screen counter. |
| 4 | A write claimed reserve space before the free-space check and the write itself; if either failed, the reserve stayed smaller than chosen. | `FileStorageService.releaseClaim` re-measures and lets the reserve grow back after any failed claimed write. |
| 5 | An accepted add or change of a passcode left one attempt counted, so the lock screen showed one fewer try left. | An accepted proposal gives its attempt back. Rejected ones still count and wait 30 s. Someone inside a library could already reset the counter by verifying their own passcode, so this adds nothing to probing. Test: `testAcceptedAddGivesItsAttemptBackSoTriesLeftStayAccurate`. |
| 6 | The microphone permission text said "Record audio memos", but in the release build the microphone is used only for camera video (App Review Guideline 5.1.1 risk). | Now: "Record sound when you take a video or make a recording in WagLock. It is encrypted on this device." |

## Open (documented, not fixed)

| # | Finding | Impact | Suggested fix |
| --- | --- | --- | --- |
| 7 | Select all from Photos imports edited photos and videos under the name "FullSizeRender", because the current (edited) resource carries that file name. The iOS-picker path keeps IMG_ names. | Cosmetic, but every edited item in a batch gets the same name, in WagLock and in exports and backups. | Name the copy after the original `.photo`/`.video` resource's base name, with the edited resource's extension (`PhotoLibraryAssetExport.write`). |
| 8 | The import progress note says "Leaving WagLock locks it right away and stops this import." With an auto-lock delay, WagLock doesn't lock, but the import still stops when you leave. | Misleading text when Auto-lock isn't Immediately. | Word the note from the auto-lock setting: "Leaving WagLock stops this import…" plus "and locks it" only for Immediately. |
| 9 | A photo-library change during a drag-to-select reloads the grid while the drag still uses the old positions. | Rare: if iCloud adds a photo mid-drag, the selection can shift onto neighbouring photos. | End the drag (`endDrag()`) or defer the reload until the drag ends when `load()` runs from the change observer. |
| 10 | Fixed-size storage measures usage by walking the whole app home directory (including tmp and Caches), and `pendingGrowth()` runs that walk on the main thread at each foreground. | With very large libraries, a short stall when WagLock comes back to the foreground in Fixed mode; and when iOS purges Caches, the reserve drifts until the next delete. | Measure only WagLock's own roots, and run `resume()`'s measurement off the main actor. |
